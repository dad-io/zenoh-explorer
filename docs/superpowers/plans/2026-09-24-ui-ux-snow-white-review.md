# UI/UX Code Review — Snow White Workbench Lens

**Goal:** Produce a detailed, evidence-backed review of Zenoh Explorer's UI/UX code and rendered behavior. It is judged against ordinary usability/accessibility standards and against Rabbit Hole's Snow White workbench paradigm. That includes a proven recipe for reproducing Snow White's causal edge-and-connection animation in our current egui 0.29 / glow renderer. The review ends in a prioritized remediation backlog that later plans can execute.

**Kind of change:** Review only. No file under `src/`, `Cargo.toml`, `.github/` or `assets/` on this branch is modified. Every task writes to the review document and its evidence folder. The one exception is T11's throwaway spike, which lives in a separate git worktree and branch and is never merged by this plan.

**Output:**

- Review document: `docs/superpowers/reviews/2026-09-24-ui-ux-snow-white-review.md`
- Evidence: `docs/superpowers/reviews/assets/2026-09-24/` (screenshots, frame captures, command output)

**Review surface:** `src/app.rs` (theme `183-299`, frame layout `303-716`, animation helpers `289-299`), `src/colors.rs`, `src/ui/{topic_tree,messages,publish,query,help}.rs`, `src/events.rs` (where results commit), `src/main.rs` (window sizing, eframe features), plus the display-facing parts of `src/types.rs` and `src/transfer.rs`.

**Our graphics stack, as established:** `eframe`/`egui` 0.29.1 with the `glow` backend and `default-features = false`. The immediate-mode UI repaints on a 66 ms throttle (`app.rs:716`). egui 0.29.1 provides:

- `Painter::add` returning a `ShapeIdx`, and `Painter::set` to fill that slot later. This allows painting beneath content that is laid out afterwards.
- Per-vertex-colored `Mesh` shapes.
- An outer-only `Shadow` (offset/blur/spread) with no inset variant.
- `ctx.animate_value_with_time` and `ctx.input(|i| i.time)`.
- `Response.rect` and panel `InnerResponse` rects.

The animation work (T9–T12) must be expressed only through these facilities, or `PaintCallback` if T10 proves it necessary. The skill forbids detached overlays, face washes and plane movement.

**Protected boundary (assumption, confirm or override):** The plus/minus pipe expander and its rotate-to-hide animation (`a7dbdfb`, `topic_tree.rs` `plus_minus_icon`) are treated as approved motion. Findings and the causal-motion design must leave its timing, path and look intact. Where it overlaps a proposed effect (such as tree-row selection), the effect stays in the row's edge band and gutter.

**Finding format:** Each finding is recorded as `F-<task>-<n>` with:

- **Severity:** S1 blocks a task or loses data/meaning; S2 causes real friction; S3 is polish; D is a design-direction proposal (Snow White adoption).
- **Location:** `file:line`.
- **Observation:** what the code or rendered UI does, citing a screenshot where it is visual.
- **Principle:** the usability/a11y rule or the Snow White section it violates.
- **Recommendation:** what to change and the egui mechanism that could do it.

Observations stay separate from proposals. A finding may not assume a feature the app does not have.

**Conventions:** Record `cargo test` and `cargo clippy -- -D warnings` output in T1 as the baseline. Screenshots come from the real running app, captured with macOS `screencapture`, at both 1400×900 (default) and 1000×600 (minimum), in light and dark mode. Motion is captured as a screen recording (`screencapture -v`) and exported to frames with `ffmpeg` at 60 fps. Connected-state captures use peer mode with multicast, or a local `zenohd` if one is available; record which.
